# 语枢 Semantica

**让 AI 取得带口径、执行证据和使用条件的数据。**

赛题二「AI 使用的大数据平台」原型。语枢在现有数仓之上增加语义执行网关，让人和 Agent 先确认问题的含义，再读取可核对的结果，并明确结果的使用边界。

## 我们解决什么问题

**SQL 算对了，AI 的决策仍然可能错。**

例如，物流账面显示承运商 A 的总体超时率为 2.8%，B 为 8.2%。但在华东和华南两个区域内，A 的超时率都高于 B。原因是 A 的业务大多位于低风险区域，B 的业务大多位于高风险区域。

如果问题改成“在相同业务构成下如何比较”，并声明华东、华南各占 50%，描述性超时率便是 A=6%、B=5%。总体率和公共构成下的率回答不同问题；它们都不自动证明更换承运商会改善业务。

传统问数往往到“返回数字”结束，Agent 还会把数字写进报告、排名和建议。语枢把过去依赖人的隐含判断，变成明确的口径、执行约定和场景使用条件。

## 可以体验什么

| 体验 | 你会看到什么 |
|---|---|
| 四幕离线演示 | 总体 2.8%/8.2% → 同区域 2%/1%、10%/9% → 公共等权 6%/5% → 带使用条件的答案 |
| 契约与证据 | 提问 → 明确口径 → 预览契约 → 人工确认 → 执行 → 下载完整证据 → 同环境重放 |
| 决策实验室 | 区分超时量、超时率和样本量，在明确成本、预算、覆盖与效力假设下比较情景 |
| Agent 数据接口 | 通过 MCP 发现目录、预览请求、确认执行并消费结构化证据；可选模型只提出可见草案 |

三层关注点是：**语义契约**说明“这个数是什么意思”；**执行证据**说明“这个数怎么算出来”；**使用条件**说明“这个数可以支持什么结论”。当前使用条件检查集中于物流比较和情景模拟，并非通用业务推理验证器。

## 如何看 Demo

**三分钟理解想法：**将仓库下载到本地，用浏览器直接打开[演示台.html](参赛材料/演示台.html)。点击“下一幕”，依次看“总体、结构、权重、条件”。第三幕默认公共权重为 50/50；拖动滑块会改变两家的率，但本例中 A 始终比 B 高 1 个百分点。无需网络或模型配置。

**进一步核对实现：**启动 Streamlit 后进入“契约与证据”，输入“8月华东履约超时率是多少？”，生成契约并选择已签收口径。核对条件后执行，再点击“在当前环境重放证据”。完整操作与路演台词见[思想进步与路演导读](参赛材料/06-思想进步与路演导读.md)。

离线演示使用四行合成计数、本地 JavaScript 计算；Streamlit 使用独立生成的合成账本执行数据库查询。离线页面的 JSON 标注为结构示意，不能当作 Streamlit 或 MCP 实际执行回执。

## 可复现启动

以下命令适用于 Windows PowerShell，使用 Python 3.11+；从仓库根目录进入项目。首次运行先生成演示账本，再启动页面。

```powershell
cd "赛题二方向一"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe data/generate_data.py --end-date 2026-09-20 --seed 42
.\.venv\Scripts\python.exe -m streamlit run app.py
```

生成器写入 `data/warehouse.duckdb`，包含 50,000 订单及相关运单、商品、客户和承运商。相对时间以数据截止日为基准。主线体验不需要调用模型；已有演示账本可直接启动，重新生成会覆盖该演示数据库。

## 范围

这是有限物流场景原型，数据均为合成。自然语言解析支持有限规则与指标，用户需确认契约；可选 LLM 负责查询草案，不构成自主反馈与修复闭环。现有实现连接 DuckDB，企业身份认证与其他数仓适配仍需后续接入。

证据包可核对完整结果、参数和版本，重放要求相同数据、语义及运行环境；它不包含原始数据快照，哈希不证明原始数据真实性。公共权重支持描述性比较；情景结果依赖声明假设，不等于因果效果或真实预测。

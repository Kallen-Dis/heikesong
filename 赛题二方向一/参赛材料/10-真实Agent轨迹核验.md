# 评委快速核验：真实 Agent 轨迹与复现边界

本页帮助核对“反馈是否改变 Agent 下一步动作”。数据为合成物流数据；保存轨迹来自有限场景，不构成模型总体成功率或跨任务泛化证明。

## 先看哪些文件

- [当前 v2 结构化轨迹](../评审实验/真实Agent轨迹/实际闭环与故障变体.json)：包含任务状态、初始产品调用、反馈、模型决策、工具参数、服务端返回、证据与定稿结果。
- [v1 问题记录](../评审实验/真实Agent轨迹/实际闭环与故障变体-v1-发现问题.json)：保留优化前后对照，不把两轮重复决策当成不同场景。
- [任务状态机](../src/task_runtime.py)：构造候选动作、校验工具调用、执行 SQL、检查覆盖并生成结构化结论。
- [模型规划器](../src/task_planner.py)：把合成任务观察和服务器允许动作交给 DeepSeek，并验证返回动作。
- [五分钟路演步骤](05-任务恢复工作台.md)：现场讲解顺序和边界表述。

## 五次真实模型决策实际证明什么

轨迹里的 v2 实际决策由 `deepseek/deepseek-flash` 产生，分布在三种故障场景中：

| 场景 | Agent 选择 | 服务端结果 | 可支持的结论 |
|---|---|---|---|
| B 的分母为 `all_shipments`，任务要求 `delivered_only` | 从 `archive` 为 B 重新获取两个正权重区域 | 参数通过校验；编译器实际查询；任务随后完成比较和定稿 | 模型在给定候选工具内选择了一项可执行补证动作；结论由服务端计算 |
| B 的华南切片缺失，备用视图可用 | 只从 `archive` 补取 B 的华南 `delivered_only` 证据 | 新证据补齐缺口，任务回到可继续状态 | 模型选择了局部补证；这条记录在补证后结束，没有声称已完成最终比较 |
| B 的华南切片缺失，备用视图不可用且不允许改范围 | `request_clarification` | 任务暂停等待用户处理，没有全域结论 | 模型没有在该观察中绕过范围约束 |

前三个动作属于第一种场景的连续步骤：`request_evidence → derive_comparison → finalize_claim`。后两种场景各记录一次模型动作，合计五次实际决策、三类场景。

轨迹 JSON 另含 `weight_reuse_offline`。它沿用同一个 task ID 和完全相同的三份模型原始响应，随后以协议模式改权重并执行重算；这三份响应是第一场景的重复记录，不是额外三次模型调用，也不证明模型在权重变化后如何决策。

## 需要一并披露的反例与范围

- 第一种场景中，模型对“为什么选备用视图”的文字理由有一处事实错误：它说主视图显式请求已妥投仍会被默认口径覆盖。代码只在请求省略 variant 时应用该默认值。模型选出的备用取证动作本身合法，服务端仍重新执行查询并检查结果；这说明**动作校验不能证明模型理由都正确**。
- 模型提示中已提供用户条件、合法动作、补证知识和不能缩范围等规则；这组证据证明有限动作集合内的受约束选择，不证明模型独立发现策略或泛化到任意数据任务。
- 改变权重后复用计数，以及整个数据快照变化后撤销证据，保存的是协议模式验证；本次没有真实模型权重扰动采样。
- 主截图展示“协议规划”模式，模型调用数为 0。协议模式是确定性演示，不能称为现场 LLM 推理。
- 备用视图与主视图来自同一仓库；它不是独立来源佐证。数据为合成数据，描述性比较不证明更换承运商的因果收益。

## 现场复现

1. 按项目 [README](../README.md) 安装锁定依赖、生成场景数据并启动 `scripts/run_workbench.py`。
2. 选择 `denominator_conflict`，观察初始产品结果与分母冲突。
3. 有本机桥接、外部 API 可用且已确认费用时，选择真实 DeepSeek，逐步查看动作、参数与服务端返回。每推进一步都会调用一次外部模型。
4. 没有桥接时保持协议规划；解释它只用于重复确定性工具链，并打开保存的 v2 轨迹核对真实模型调用。
5. 使用 `missing_slice` 分别演示备用视图可用和不可用两种状态；改变权重后由服务器复用有效计数重新比较。

真实模型调用需要本机私有桥接，不含在公开交付副本中；原始保存记录便于审查，但重新调用外部模型不保证逐字重现相同决定。

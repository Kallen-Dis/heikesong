# 语枢：思想进步与路演导读

适用交付版本：v0.2.1（历史标签 `赛题2-Astra评审优化-庄子由`）。交付副本不含 Git 分支元数据。这份文档帮助第一次阅读的人理解变化，并提供可以直接照着演的稿子。当前主角是“任务恢复工作台”；原语义网关仍是它的计算与口径底座。

## 先用一分钟抓住核心

以前，我们关心的是：AI 提出的数据请求，能不能表达正确口径、执行真实查询，并留下可检查的证据。现在，我们继续问：当第一次返回的证据不满足任务时，AI 怎么继续？

比如用户要比较两家承运商的已妥投超时率，已有产品却给了不同分母。平台会说明具体哪一个字段冲突；模型看到反馈，选择按正确口径重新取证。若只缺华南，就只补华南；若没有访问权限，就请求用户处理。它不能把缺数据填成零，也不能悄悄删掉用户要求的区域。

最后，服务器用真实计数生成带条件的结论。改权重可以复用计数；数据变化会撤销旧证据与结论。我们要展示的进步，是让失败成为下一次合法数据请求的起点，并在恢复过程中保留用户的原要求。

## 这版到底向前走了哪一步

### 1. 从三层正确性理解问题

第一层是**算得对**：SQL 有没有按指定表达式执行，分子分母有没有算错。第二层是**意思对**：这里的“超时率”以已妥投还是全部运单为分母，以发货还是妥投时间筛选。第三层是**足以回答当前问题**：两家是否覆盖同样区域、使用同样构成，缺证时还能不能比较，历史比较是否足以推出换承运商后的改善。

原版已经强调，正确数字不自动支持正确决策，也有契约、可比性检查和证据包。原版的查询契约、数学反例与条件实验室是分别成立的演示材料；当前工作台把检查结果接进同一个任务的执行：不满足条件后，任务不再只停在一张错误提示上，而是进入补证、重算、澄清或停止的下一步。想先理解原版，可以读 [语义执行网关版本导读](07-语义执行网关版本导读.md)。

### 2. 失败变成模型下一次工具调用的输入

初始化时，既有产品 A 默认按已妥投查询，B 默认按全部运单查询。它们都执行了真实 SQL；B 的结果符合自己的产品口径，只是不符合这次任务。这里不能讲成“模型先犯错、随后自我纠正”。模型接手的是已经存在的产品证据。

平台把问题写成具体反馈：目标要求 `delivered_only`，实际收到 `all_shipments`，冲突位于分母口径。模型再提出一个动作，服务端校验并执行。这使 AI 消费的东西从一份孤立数字，变成“数字、使用条件、缺口以及当前可选动作”。

模型负责提议下一工具；编译器生成并执行参数化 SQL；服务器管理证据和结论。模型不能提交自由 SQL、编造一个结果数值，或把自己写下的“已授权”当成真实权限。模型解释也可能有误，动作是否有效仍以实际执行和条件检查为准。

### 3. 恢复任务，同时保留用户的要求

用户要求已妥投、相同发货时间窗，并覆盖所有正权重区域。恢复不是“想办法输出一句话”，而是“继续完成这些要求”。缺华南时，系统不能删掉华南重新归一化，也不能填零。无权限时，模型只能请求澄清或停止。

人类可以先开放“仅华东”的授权选项，再明确授权新范围。开放选项还没有改变任务；真正授权后，结论必须写明只比较华东。它完成的是改过范围的新任务，原来的完整区域问题仍没有完成。

这里的任务来自结构控件：固定口径、窗口、权重与范围。文字框供人核对目标，当前没有实现任意自然语言限定词的自动理解。我们先把有限任务中的执行责任做清楚，再讨论扩大任务类型。

### 4. 用一个会翻转的例子说明“条件”不是装饰

工作台使用下面这组自建合成数据，每个区域另有 25 条在途运单：

| 承运商 | 区域 | 已妥投 | 超时 | 已妥投超时率 |
|---|---|---:|---:|---:|
| A | 华东 | 900 | 18 | 2% |
| A | 华南 | 100 | 12 | 12% |
| B | 华东 | 100 | 4 | 4% |
| B | 华南 | 900 | 72 | 8% |

同一个任务给两家使用共同区域权重。华东 20%、华南 80% 时，A 为 `20%×2%＋80%×12%=10%`，B 为 `20%×4%＋80%×8%=7.2%`，B 较低。华东改为 80% 时，A 为 4%，B 为 4.8%，A 较低。A 在华东占优、B 在华南占优，所以目标业务构成会改变排名。

原版独立数学演示中，A 在两个区域都比 B 高 1 个百分点；统一权重后无法靠改共同权重让 A 更优。它用于解释总体构成误导。这版用于解释任务条件改变如何驱动重算，两个例子不要混用。

### 5. 缺证时，反例告诉我们为什么不能猜

若 B 的华南证据缺失，已知 B 华东为 4%。仍以华东 20% 为目标，假设 B 华南为 0%，B 加权率就是 0.8%，优于 A 的 10%；假设为 20%，B 就是 16.8%，劣于 A。两种补全都能与目前已知片段相容，却给出相反排名。

这些数值只用于说明“信息不足”，界面明确标为假设补全，不能当作真实观测。备选视图有权限时，模型可以补取 B 华南，得到真实已妥投计数 900、超时 72，再继续比较。备选视图来自同一仓库，是另一条取证路径，并不是独立来源对真实性的交叉证明。

### 6. 复用证据，也承担撤销结论的责任

改权重不会改变原始区域计数，系统保留证据、清空比较、撤销原结论；下一次计算复用这些计数，不再执行取证 SQL。点击权重按钮只提交新条件，仍要执行下一步才会出现新比较。

数据更新则不同。当前实现用整个合成快照检测版本变化，撤销全部证据和原结论，再重新取证。这是保守、可观察的恢复机制，尚不是只让受影响结论失效的精准增量血缘。旧结论不会因曾经算对而自动继续有效。

### 7. 用实现解释思想，但把能力范围说清楚

现有真实轨迹记录了三类有限场景：分母冲突后重新取证、华南缺片后从备选视图补证、备选不可用后请求澄清；还包含取证后的计算与定稿。提示已经提供了合法修复知识，观察支持的是模型依据反馈选择受约束动作，尚未证明它独立发现策略或跨任务泛化。

描述性比较完成后，“换承运商是否真的改善”仍需独立的因果与成本证据。界面定稿指的是当前条件下的历史描述任务完成。这个边界帮助我们准确说出平台交给 AI 的能力，也留下下一步工作的方向。

## 相对上一版的进步表

| 要解决的事 | 原语义网关已有的重点 | 当前任务恢复工作台的进步 |
|---|---|---|
| 口径歧义 | 明确指标、预览契约、用户核对 | 既有结果冲突后给出字段反馈，接入下一工具 |
| 查询执行 | 受支持结构表达、参数化 SQL、结果证据 | 延续计算底座，模型选择补哪一份证据 |
| 数据缺口 | 检查覆盖与可比性 | 显示相反假设，局部补证后继续原任务 |
| 用户范围 | 声明比较条件 | 无权自动缩范围，人类分两步开放并授权 |
| 条件改变 | 展示共同权重与条件实验 | 条件变化实际撤销结论，复用计数重新计算 |
| 数据更新 | 版本检查与同环境重放 | 撤销当前快照证据，恢复后才生成新结论 |
| AI 的位置 | 可以提出查询草案 | 接收反馈，提出下一动作，形成可检查闭环 |
| 演示组织 | 查询契约、数学反例、条件实验分别说明能力 | 同一工作台内保留任务、证据、反馈与下一动作 |

## 路演前准备：一次任务、一个主屏

按 README 安装依赖后，在 `赛题二方向一` 目录准备数据并启动本地服务：

```powershell
.\.venv\Scripts\python.exe data/generate_data.py      # 生成数仓与工作台场景表
.\.venv\Scripts\python.exe scripts/run_workbench.py
```

用浏览器打开 [本地工作台](http://127.0.0.1:8766)。不要直接双击 HTML。可用 [桌面截图](任务恢复工作台-桌面.jpg) 预先熟悉三栏：左侧任务条件，中间反馈与轨迹，右侧比较与结论。

提前准备好口径冲突起点、华东 20%、备选视图启用、未授权缩小范围。选择“真实 DeepSeek”前，确认本机桥接已配置且可用。真实模式每步调用外部 API；协议规划是明确标注的确定性离线策略，两者使用同一实际查询和检查链。

协议模式安装本项目 Python 依赖即可体验。当前真实模式调用本机已安装并配置模型访问的 `deepseek-worker` 桥接；换到其他机器时需另行配置，安装 `requirements-lock.txt` 不会自动完成模型桥接。没有桥接时，先用协议模式排练，再对照保存的真实模型轨迹阅读。

**自动运行会在有效比较出现后暂停**，留给人类点击“定稿描述性结论”，也可以点击“由规划器定稿”让模型单步提出定稿。仅计数齐备而 `comparison` 仍为空时，需要继续计算，不能因为状态名是 `ready` 就宣称已有比较。自动运行还会在澄清、定稿或十步上限停下。

五分钟主线只做三件事：修复分母、改目标权重、补区域缺片。权限与数据更新在八分钟扩展展示。每次重置是新的演示任务；先讲完当前结果，再明确说“接下来换一个故障”，避免把几个任务连成一个并不存在的成功记录。

## 五分钟可直接照演的流程与完整口播

下面时间是讲述节奏，真实 API 耗时不能保证。等待时解释已出现的反馈，不重复点击。若预演发现延迟无法容纳，按下文预案使用协议演示与已保存真实轨迹。

### 0:00—0:45：让观众知道我们要回答什么

**屏幕操作：** 口径冲突起点、华东 20%，点击“开启 / 重置任务”。指向左侧比较契约和中间冲突反馈。

**口播：**

> 大家好，我们的作品叫语枢。今天只回答一个问题：在指定的区域构成下，承运商 A 和 B 谁的已妥投超时率更低？用户要求相同分母、相同发货窗口，并保留华东和华南。现在，两份既有产品都查到了真实数据，但 A 默认用已妥投，B 默认用全部运单。两份查询各自可以算对，却不能直接完成这个比较。语枢先指出具体冲突，再让 AI 决定下一步。

### 0:45—1:40：展示“反馈进入下一工具”

**屏幕操作：** 点击“真实 DeepSeek”，点击“自动运行”。等待出现 A=10%、B=7.2%。展开一条模型取证轨迹的“参数 / 返回结果 / 决策 JSON”；如需展示 SQL，再展开对应证据的“实际执行 SQL”。

**口播：**

> 这里切换到真实模型。它收到的不是一句“出错了”，而是分母字段的实际值、目标值以及合法动作。模型提出重新获取 B 的已妥投证据，平台校验请求，再用原有编译器执行 SQL。模型没有自己填写答案，计算也不靠它心算。取证充分后，下一工具复用计数生成比较。这里 A 是百分之十，B 是百分之七点二。平台会自动停在比较已经准备好的位置，等待定稿。

### 1:40—2:40：让条件真的改变结果

**屏幕操作：** 点击“定稿描述性结论”。点击“华东 80%”，指向旧结论失效与证据复用提示；点击“执行下一步”，等 A=4%、B=4.8%。不要在等待重算时把空白比较读成新结果。

**口播：**

> 这张结论卡写明了区域、权重、口径和版本。现在用户改变目标：华东业务占百分之八十。旧结论立即失效，但各区域的真实计数没有变，所以仍然可用。点击下一步后，我们只重新计算，没有再次取数。A 变成百分之四，B 是百分之四点八，排名翻转了。这不是平台推翻事实，而是问题的业务构成变了：A 在华东较低，B 在华南较低。条件不仅写在说明里，也改变执行与结果。

### 2:40—4:10：缺一片时，为什么不能直接回答

**屏幕操作：** 点击“华东 20%”；起点选择“数据缺片”，点击“开启 / 重置任务”。若按钮显示“启用备选视图”，先点击启用；确认按钮显示“关闭备选视图”，即当前备选已启用。展开“查看平台反例”。点击“自动运行”，等待补证和比较。展开补证轨迹，指出仅请求 B 华南。

**口播：**

> 接下来换一个故障，开始新的演示任务：B 的华南证据缺失。平台先告诉我们为什么不能猜。若假设缺失区域的率为零，B 会更低；若假设为百分之二十，A 会更低。这两种都是假设，不是真实数据，说明目前信息不足。模型接下来选择从有权限的备选视图只补 B 华南，已有的 A 和 B 华东计数继续保留。补到了九百条已妥投、七十二条超时，才恢复完整区域比较。备选视图与主视图来自同一个仓库，它提供另一条取证路径。

### 4:10—5:00：准确解释这件作品完成了什么

**屏幕操作：** 比较出现后点击“定稿描述性结论”。指向结论条件与“描述比较 ≠ 干预效果”，最后指回中间执行轨迹。

**口播：**

> 现在，这个条件下的历史描述比较已经完成。但换承运商以后是否改善，还没有因果和成本证据，我们不会把这个问题也标成成功。语枢的主要进步，是把错误和缺证变成下一次合法数据请求，同时保留用户的要求。模型选择动作，数仓负责计算，平台检查证据是否足够，并对结论的使用条件负责。我们已经在有限合成场景跑通这个恢复过程；下一步希望扩展更多任务和数据来源，验证这套机制能否稳定复用。

## API 延迟或现场不可用时怎么说

提前打开 [已保存真实闭环](../评审实验/真实Agent轨迹/实际闭环与故障变体.json)，同时准备 [实现与验收说明](../评审实验/03-实现与验收.md)。保存文件记录的是此前已经发生的真实模型决策和工具结果，不是现场重新调用，也不是视频中的预设动画。

若 API 已结束并返回失败，再切“协议规划”继续。请求仍进行时，模式按钮会禁用；“停止自动运行”也要等当前请求结束。此时先展示已保存轨迹与说明，不能承诺立刻切换；超时后用“重新连接”检查服务器实际状态，避免盲目重发。

**可直接说：**

> 现场模型请求目前未完成。我先展示此前保存的真实调用记录，它包含原始输出、用量和服务端结果；这不是本次现场调用。后续界面操作采用明确标注的离线协议策略，仍执行真实查询和条件检查，展示恢复机制。离线策略的动作选择来自规则，不能作为模型推理的现场证据。

若需要严格压到五分钟，可从一开始就用协议规划跑完整操作，并在第一段明确说明，再用保存轨迹展示真实模型已做过哪些选择。不要为了赶时间把两种运行方式混称为“AI 全程自主运行”。

## 八分钟扩展：加上权限与撤销

沿用五分钟主线，然后按下面顺序增加三分钟。扩展操作可使用协议规划以控制时长，切换时明确说明。无需把每一段都重新跑到定稿。

### 5:00—6:15：无权限，不能自动缩小任务

**操作：** 选择“数据缺片”并重置；**重置后**检查备选状态，点击“关闭备选视图”，然后“执行下一步”，等到请求澄清。点击“开放仅华东的授权选项”，再点击反馈区“用户显式授权仅比较华东（改变任务范围）”。最后执行下一步得到华东比较，必要时定稿。

服务端重置接口默认启用备选；当前前端会把备选开关状态带入重置。无论从哪个入口开启任务，都采用“先重置、再核对并关闭备选”的顺序，避免把无权限演示变成自动补证演示。

**口播：**

> 现在我们开始一个无权限的缺片任务。模型没有可用的备用取证权限，于是请求用户处理。它不能自己给自己授权，也不能为了交差偷偷只比较华东。这里我先开放授权选项，任务范围尚未改变；再明确授权仅华东，才形成新目标。华东的数据已经齐备，所以能够继续计算 A 百分之二、B 百分之四。这个结论只覆盖华东，不能说原来的两区域任务已经完成。恢复也包括知道什么时候必须把选择交回用户。

### 6:15—7:00：数据变化撤销原证据

**操作：** 在有效比较或定稿后点击“导入数据更新”。指向证据“已失效”、旧结论撤销和数据版本变化。此段只演失效，不强求在剩余时间重跑全部取证。

**口播：**

> 刚才改变权重，可以继续用原计数。现在数据本身更新，旧计数不能继续代表当前版本，平台会撤销全部快照证据与结论。我们当前实现的是整个合成快照的失效检测，还没有精准追踪哪一条数据影响哪一项结论。因此这里证明的是不会无声沿用旧结论，而不是已经实现增量血缘。

### 7:00—8:00：把作品放回大数据平台题目

**操作：** 指向三栏与一条可展开轨迹；展示保存真实闭环的入口，结束在撤销状态也可以，不称本轮恢复已经完成。

**口播：**

> 对 AI 来说，数据平台要交付的除了数字，还有这个数字的含义、适用条件，以及条件不满足时能做什么。我们的本体和口径定义负责统一意义，原有编译器和 SQL 引擎负责计算，新工作台把反馈、补证、复用与撤销连接成执行过程。真实模型已在三个有限场景选择过合法下一动作。修复知识也已经写进提示，我们尚未证明模型能独立发现新的策略。今天展示的是一条可以检查的任务恢复路径，它为后续扩展提供了明确接口和验收方向。

## 两个短介绍，适合开场或被临时点名

### 30 秒

> 语枢让 AI 遇到数据冲突后继续完成任务。用户要求比较已妥投超时率，但已有产品分母不同；平台返回具体冲突，模型选择重新取证，服务器用真实计数生成带条件的结论。缺区域就补证，无权限就请用户处理，改条件或数据会撤销旧结论。这版重点是保留用户要求的任务恢复。

### 90 秒

> 我们做的是语枢，一个建立在现有数仓之上的 Agent 语义执行网关。这次把重点推进到任务恢复：当第一次证据不满足要求时，AI 怎么继续把事情做完。
>
> 用户想比较两家承运商的已妥投超时率。已有产品都执行了真实查询，却用了不同分母。平台定位冲突，模型再提出合法取证动作，原有编译器执行 SQL，服务器检查覆盖并计算比较。模型不能自由写 SQL、填一个答案或给自己授权。
>
> 我们还让条件产生可见影响：华东权重从百分之二十变到百分之八十，A 与 B 的排名翻转；区域计数仍可复用。若华南缺片，假设不同的缺失值会得出相反结果，所以必须补证；无权限就请求用户选择。数据更新则撤销旧证据与结论。
>
> 目前已在合成物流场景跑通真实模型选择和服务端执行。完成的是有条件的历史描述比较，换承运商的因果收益仍未证实。我们希望让数据平台给 AI 提供可继续行动、也能知道何时停止的能力。

## 五个高频问题与回答

**1. 这和普通问数、Text-to-SQL 有什么区别？**

普通查询主要解决把请求变成计算。这版关注查询结果不满足任务之后怎么办：反馈指出具体冲突，模型选择局部取证，平台保留用户条件并继续检查。我们复用现有 SQL 计算能力，展示的是查询之间的任务恢复机制。

**2. 模型到底做了什么，会不会只是固定流程？**

真实模式下，模型读取当前反馈、证据和允许动作，每次提出一个下一工具。已保存轨迹分别出现重取证据、只补华南、请求澄清等选择。离线协议确实是有限确定性策略，界面单独标明。提示包含修复知识，目前没有证明模型自主发现策略或跨场景泛化。

**3. 为什么备选视图补到了，就认为可以继续？**

因为它实际查询得到同仓、同窗口、同口径的缺片计数，补足了这次比较的覆盖条件。它不是独立真实性来源；我们的主张是当前任务可以在声明数据条件下继续，不是这批数据已经获得外部真实性认证。

**4. 为什么改权重会翻转，能不能说明换承运商更好？**

A 在华东为 2%，低于 B 的 4%；A 在华南为 12%，高于 B 的 8%。共同权重决定这两部分各占多少，因此排名可以翻转。它描述指定构成下的历史率，实际换承运商还涉及混杂、干预和成本，不能从这个差值直接推出收益。

**5. 这版可以称为通用 AI 数据平台吗？**

现在是现有数仓之上的有限原型：结构控件定义任务，真实模型选择受约束动作，编译器、覆盖检查与服务端结论形成闭环。它说明了一种平台接口方向。更多行业、自然语言任务、独立数据来源与更细版本依赖都还需要扩展和验证。

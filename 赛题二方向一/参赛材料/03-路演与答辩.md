# 5分钟路演、答辩与提交文案

> 本文是原四幕数学演示的历史剧本。当前舞台主屏与新五分钟流程见 [任务恢复工作台](05-任务恢复工作台.md)，它在一个页面执行完整任务链。原演示保留为数学解释。

## 1. 路演原则

只让评委记住一个命题：**AI 数据平台的责任不能止于算出一个正确数字。**

用一条完整叙事，不罗列所有模块。先给出直觉，再让事实反转，随后解释平台怎样把隐含使用条件变成接口约束。国际赛事的完整链路思路见 [参考资料](04-国际参考与演进.md)。

舞台主屏使用 `演示台.html`，离线即可演示；需要技术细节时切到 Streamlit「契约与证据」。不要现场安装依赖、输入密钥或长时间跑评测。

## 2. 5分钟主剧本

| 时间 | 操作 | 核心台词 |
|---|---|---|
| 0:00–0:35 | 演示台第一幕，总体A2.8%、B8.2% | “如果AI拿到这两个数字，会建议优先换掉谁？大多数人会指向B。计算确实正确。但这个建议还缺一个条件。” |
| 0:35–1:15 | 第二幕展开两个区域 | “同一区域里，A反而都更差。A的大部分订单在低风险区域，B的大部分在高风险区域。数字没有骗人，问题的含义变了。” |
| 1:15–1:50 | 第三幕声明50/50公共构成，滑块现场调整 | “如果比较的是同一种业务构成，A是6%，B是5%。平台不能替你猜目标构成，也不能从这个结果承诺换承运商的真实收益。” |
| 1:50–2:35 | 第四幕三层条件；解释产品定位 | “语枢在现有数仓之上提供Agent语义执行网关。AI取得的是带条件的答案：意思明确、计算有证据、结论有边界。” |
| 2:35–3:25 | Streamlit契约页输入“8月华东履约超时率是多少？”，选择已签收口径，预览后执行 | “继续刚才的承运商问题：我们先明确如何统计超时。本体规定合法口径，确认后生成合同，执行检查版本、范围和关联粒度。模型提出草案，编译器计算。” |
| 3:25–4:00 | 下载/重放同一结果；展示契约核心字段 | “每个数字附带来源、参数、完整结果和版本。这里重放的是同一本地数据，证据包没有伪装成完整数据快照。” |
| 4:00–4:30 | 决策实验室展示预算与效力假设 | “条件不足，不代表任务结束。我们可以改问、声明权重，再把观察到的历史率与声明的效力分开，计算有条件的方案，不能承诺未经验证的真实效果。” |
| 4:30–5:00 | 回答赛题三问，停在核心命题 | “AI使用类型化的语义接口；本体是共同语言，还要执行和使用条件；传统数仓继续计算，语枢增量融合。我们让AI知道这个数能说明什么，以及还不能推出什么。” |

台词中的停顿比加速讲模块更重要。第二幕展开后停2秒，让评委自行察觉反转。第三幕只改一次权重，不沉迷滑块。

以上第一至第三幕为明确合成的数学反例，不表示实际模型曾给出“替换B”的建议。

## 3. 8分钟扩展

增加三个各1分钟的部分：

- 展示真实Agent规划接口与目录：原始目标、模型草案、必须核对的翻译、澄清和契约。不接模型时明确使用协议/确定性演示。
- 展示一个拒绝继续的情况：华东角色请求华南聚合、定义变化后旧合同失效，或关联粒度异常。只展示一个最顺手的例子。
- 展示演进路线和边界：已有DuckDB适配、企业快照与身份认证、语义元数据互操作，以及独立评测。

决赛问答仍独立保留，不挤进8分钟。

## 4. 视觉与表达

- 主标题：“SQL 算对了，AI 的决策仍然可能错。”
- 英文短句：“Meaning before action.”
- 三个阶段标签：“确认意义 / 携带证据 / 检查使用条件”。
- 数字优先，术语靠后。第一幕不出现本体、MCP、哈希等缩写。
- 不用“打败某大模型”“百分之百企业正确”“全球首创”等强口号。
- 将三层语义用一个持续变化的答案对象表现，而非三张互不相干的架构图。

## 5. 高频答辩

**Q：这是不是普通语义层加MCP？**

A：目录与MCP本身确实已有成熟方案。我们的参赛贡献是把数字进入比较和建议后的使用条件纳入闭环：先约定口径，再检查执行与版本，最后在物流比较场景要求共同支持、明确业务构成和假设。用构成反转例证明这个缺口。

**Q：既然SQL正确，为什么还说结论可能错？**

A：汇总SQL回答的是各自现实构成下的超时率。更换决策隐含“如果用相同业务比较，谁更好”。这两个问题不同。我们展示的不是算术错误，而是问题和使用条件没有对齐。

**Q：标准化就能证明B更好吗？**

A：只能给出声明构成下的描述性率。没有控制其他混杂，也没有干预证据，所以不能承诺实际替换的效果。

**Q：本体到底有没有价值？**

A：有，它把口径和关系变为共同语言。没有本体，Agent容易重复解释；只有本体，数据质量、权限、快照和可比性仍未解决。语枢把它接到执行与使用条件。

**Q：AI在哪里？大量逻辑是规则。**

A：模型负责开放目标的规划与解释，平台负责确定性编译和约束。项目提供可选真实LLM草案接口及MCP数据工具；离线路演不冒充模型运行。下一阶段最重要的是记录真实Agent计划修正的完整轨迹。

**Q：模型可能忽略你给的限制。**

A：是的，单靠文字不能保证行为。因此数据库端会执行范围、版本、粒度与编译检查；比较组件也不给出没有证据的行动批准。我们不能证明外部模型不会脱离工具编造，当前保证范围是这些受约束接口。

**Q：哈希是不是可以被攻击者重新计算？**

A：可以。当前哈希用于检测改动与本地一致性，不代表身份、签名或授权。执行端独立检查服务端策略并重新编译。企业环境还需认证与签名机制。

**Q：你们100%正确吗？**

A：在特定自建回归和开发后的反例集上有对应结果。它们不等于任意语言、真实企业数据或国际榜单。我们保留独立反例首次失败，避免以漂亮百分比掩盖漏条件。

**Q：为何不做完整跨境或供应链优化？**

A：我们的选题是方向A。物流是暴露语义和使用条件的具体场景；决策实验室用于证明数据如何被消费，不把项目扩张成另一个赛题的大而全平台。

**Q：为什么只支持单订单最多一运单？**

A：这是当前合成账本的粒度合同。拆单和多运单会使订单金额JOIN放大，应该升级关联策略，不能直接删掉检查。明确这一点比默默返回错误聚合更可靠。

## 6. 提交摘要

### 约250字版本

语枢Semantica面向“AI使用的大数据平台”，提出在现有数仓之上增加Agent语义执行网关。我们用一个区域构成反转案例证明：SQL计算正确，仍不足以支持业务比较和行动建议。系统将普通查询结果升级为带指标口径、粒度、时间、版本、来源和使用条件的答案对象，通过明确澄清、两阶段契约、参数化编译、关联质量阻断和完整证据重放支持可复核的数据使用。物流实验室区分超时量、超时率与样本量，在明确成本和效力假设下做有限情景比较。项目使用合成数据，提供Streamlit原型、离线演示台及MCP接口；本体是共同语言，执行校验与使用条件补足其边界。目标是让AI知道数字能说明什么，以及还缺什么证据。

### 50字版本

语枢让AI取得带口径、证据和使用条件的数据，用区域构成反转展示“算对不等于用对”，为现有数仓增加语义执行网关。

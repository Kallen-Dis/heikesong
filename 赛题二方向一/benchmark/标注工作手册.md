# AmbiQuery-120 双人复核工作手册

> 面向对象：不懂技术也能上手（全文无前置知识要求）
> 预计耗时：**每人 1.5–2 小时**（可分段，随时中断继续）
> 产出：`eval/review_<你的名字>.jsonl` + 参与一次 20 分钟的仲裁会

## 0. 三十秒版（TL;DR）

**我们做了什么**：给"语枢"系统建了一套 120 道题的考试题库（含标准答案）。
**你做什么**：作为"独立质检员"，逐题检查"题目读得通吗？标准答案对吗？该提问的地方标对了吗？"，输入 `y`（确认）或 `n`（有问题+写备注）。
**为什么是你**：两个人独立检查 = 堵住"自己批改自己"的质疑，这是比赛评分（成果完整性与可用性 30 分）的硬通货。
**怎么开工**：看完本手册 → 跑第 3 节的准备命令 → 按第 4 节逐题判定。

## 1. 术语速查表（看不懂就回这查）

| 术语 | 大白话 | 例子 |
|---|---|---|
| **gold SQL** | "标准答案的计算式"——一段数据库查询，机器跑一遍得到的数字就是标准答案 | `SELECT SUM(order_amount) FROM orders WHERE ...` |
| **标准答案** | gold SQL 跑出来的结果 | 例如 `35,412,600.85` 或 `0.1756` |
| **澄清点 / 澄清卡** | 题目有歧义时，系统应该**先弹卡片问用户**（而不是自己猜）。"期望澄清点"= 我们要求系统必须弹卡的地方；为空 = 系统应直接作答 | 「金额」（3 种算法）→ 必须弹卡 |
| **陷阱题** | 题目问的东西数据里根本不存在，**正确行为 = 拒绝回答**（说"数据不足"），编任何数字都算错 | "退货率"（没有退货表） |
| **compare / 判分方式** | 机器怎么判这道题对错 | 比数字 / 比文字 / 人工看 / 看是否拒答 |

### 六类题目分别考什么（每类 20 题）

| 类别 | 通俗说法 | 例 |
|---|---|---|
| A 同义词 | 说黑话/口语，系统能不能懂 | "妥投率""单量""大盘" |
| B 口径歧义 | 问题没说清，系统该不该追问 | "8月的金额是多少？" |
| C 实体歧义 | 一个词指两个东西 | "苹果"= 商品品牌？客户公司名？ |
| D 时间理解 | 模糊时间该怎么算 | "最近""本月""近7天" |
| E 多跳推理 | 一句话要连好几张表 | "超时运单最多的承运商是谁？" |
| F 陷阱题 | 不该答的题别乱答 | "毛利率是多少？"（无成本数据） |

## 2. 约定清单（判定答案的依据，很重要！）

复核时遇到这些词，**按以下约定判断答案对不对**（这套约定已写进各题备注）：

| 约定 | 内容 |
|---|---|
| 时间基准 | 所有相对时间以**数据截止日 2026-09-20** 为基准："上月"=2026年8月，"本月"=9月1日–9月20日，"近7天"=9月14日–9月20日 |
| 口径第一选项 | 有歧义的题（如"金额"），标准答案取**澄清卡的第 1 个选项**（金额=毛额；超时率=超时运单/已签收运单；"最近"=近7天） |
| 超时定义 | 实际签收时间晚于承诺送达时间（只有已签收的运单才可能超时） |
| 妥投率 | 已签收运单 ÷ 全部运单（运输中的算分母） |

## 4. 复核流程（核心工作）

### 4.1 每题看三件事

工具会逐题显示：题目、标准答案（数字）、**中文对照清单**、期望澄清点、出题备注。

> ⚠️ **先记住一件事：不需要你自己算数字，也不需要上网搜。**
> 这是咱们自建的模拟数据库，全世界只有这份库知道答案——你的角色是“翻译质检员”：
> 检查“题目 → 标准答案”的翻译链有没有跑偏，而不是当人肉计算器。

| # | 检查什么 | 判定标准 |
|---|---|---|
| ① | **题目读得通吗** | 像正常人会问的话吗？有没有明显的错别字/病句？ |
| ② | **标准答案对吗** | 拿题目对照工具给出的**中文清单**：题目里的每个限定词（时间/地区/品牌/指标算法），在清单里逐条找对应；再瞄一眼数字量级（率→0~1 小数；条数→整数；金额→较大数） |
| ③ | **期望澄清点合理吗** | 题目里有歧义词（金额/最近/苹果）→ 应该列澄清点；没有歧义词 → 应该为空、“直接作答” |

#### 实例演练：A01「8月华东区的妥投率是多少？」

工具会显示这样的对照清单：

```
📏 标准答案：0.978966...
🧭 快速对照清单（逐条核对，不用重算数字）：
   · 算法：已签收运单 ÷ 全部运单（比率）
   · 时间：2026-08-01 ～ 2026-08-31（含首尾）
   · 地区 = 华东
   · 量级提示：结果应为 0~1 之间的小数
```

逐条对照（三秒钟）：

1. 题目说“8月” → 清单有“8月1日–8月31日” ✅
2. 题目说“华东区” → 清单有“地区 = 华东” ✅
3. 题目说“妥投率” → 算法正是“已签收 ÷ 全部” ✅
4. 0.9789 是 0~1 的小数，量级正确（约 97.9% 的包裹被签收，合理）✅

→ 全部对上，输入 `y`。

**常见的“打 n”情况**：清单里时间/地区与题目不符；答案出现负数或量级离谱（比如“平均耗时”出现几百万）；题目有歧义词但“期望澄清点”没列。

### 4.2 输入判定

- 输入 **`y`** = 确认没问题（大多数题目会是 y）
- 输入 **`n`** = 有问题 → 工具会请你写一句备注（**写清楚哪里不对**，例："数字 0 是不是因为该客户当月没下单？建议加个有数据的客户"）
- 输入 **`s`** = 跳过（拿不准、想回头再看）

> **规则：拿不准就写 `n` 或 `s`，不要硬选 `y`。** 分歧不可怕，装懂才可怕——仲裁会解决它。

### 4.3 中断了怎么办？

直接重新运行同一条命令，**自动跳过已做过的题**。所以可以分几次做完（比如今天做 A/B 类，明天做 C/D 类，用 `--only A` 等参数只跑某一类）。

## 5. 两个人怎么配合

### 5.1 独立性铁律

**各自独立复核，不许商量。** 不要对答案、不要讨论某道题——独立才有交叉校验的价值。（可以在同一台电脑上轮流做，或各自电脑上做。）

### 5.2 做完后生成一致性报告

两个人各自做完自己的名字（如 `小明`、`小红`），由一个人运行：

```powershell
python scripts/compare_reviews.py eval/review_小明.jsonl eval/review_小红.jsonl
```

会生成 `eval/review_agreement.md`：
- **一致率**（两人都确认的比例）——这个数字会写进比赛材料
- **仲裁清单**：两人结论不一致的题，逐条列出

### 5.3 仲裁会（20 分钟）

对不一致的题开会讨论。**分歧通常只有三种原因**，对症下药：

| 原因 | 长什么样 | 怎么处理 |
|---|---|---|
| ① 读法不同 | 你说数字对，他说"这题应该弹澄清卡" | **这恰好说明题目有真歧义** → 记下结论：改成"应弹澄清卡"或写明固定读法 |
| ② 有人看错 | 一方理解错了 SQL 或题目 | 一起把 gold SQL 跑一遍看结果，以数据库为准 |
| ③ 题目本身不行 | 两人都说不清哪种读法对 | **重写题目或弃题**（有备胎题，弃几道无所谓） |

仲裁结论由一人统一记录，之后更新题库文件（**复核人不要直接改 jsonl 文件**，避免冲突）。

## 6. 常见问题（FAQ）

**Q1：我完全不懂 SQL，能做好吗？**
A：能。每题下方工具会自动列好**中文对照清单**（算法/时间/筛选/量级提示），照着逐条核对就行，不需要读原始 SQL。你只判断两件事：① 清单和题目对得上吗；② 数字量级合理吗。

**Q2：结果数字是 0 或者很怪，是错了吗？**
A：可能是真实情况（比如某个客户当月确实没下单）。这正是你要留意的：写 `n` 备注"数字为 0，请确认是否该换有数据的对象"。

**Q3：我觉得题目本身写得不好 / 答案应该改？**
A：**不要直接改文件**。在你的判定里写 `n` + 具体建议，仲裁会上统一决定怎么改。这正是复核的价值。

**Q4：两人进度不一样怎么办？**
A：各自独立跑，工具按人存档（`review_名字.jsonl`），互不影响。都做完再跑对比脚本。

**Q5：能只复核一部分吗？**
A：正式记录需要**每人都完成全部 120 题**。但可以分段：`--only A` 只跑 A 类，`--limit 10` 只跑前 10 题，进度自动累计。

**Q6：工具报错了怎么办？**
A：把完整报错截图发群里。检查是否在 `d:\黑客松\semantica` 目录下运行。

**Q7：我的判定存在哪？会丢吗？**
A：每答完一题**立刻自动存档**，存在 `eval\review_你的名字.jsonl`（一个文本文件，用记事本就能打开看）。关掉终端、电脑重启都不会丢已做的部分——一行代表一道题。

**Q8：一次做不完怎么办？**
A：直接关掉就行。下次运行**同一条命令**（名字保持一致，如"小明"就一直是"小明"），工具会自动跳过已做过的题、从断点继续。看开头显示的"已完成 X 题"就是你的进度。也可以分段做，比如今天只做 A 类：`--only A`。

**Q9：朋友在另一台电脑做的，怎么合到一起？**
A：让他把他的 `review_他的名字.jsonl` 文件发给你（微信/QQ 传文件即可，很小的文本文件），放进 `d:\黑客松\semantica\eval\` 文件夹，然后按 5.2 节命令跑对比。**注意：不要删改别人的文件。**

**Q10：某题手滑判错了，想重做？**
A：用记事本打开你的 `review_你的名字.jsonl`，删掉那一行（一行 = 一题），重新运行命令，工具就会把那题再问你一遍。**只允许改自己的文件。**

## 8. 附录：题型速览（附实例）

### A 同义词类——「8月的大盘是多少？」
考察：把口语（"大盘"）翻译成专业指标（GMV 成交总额）。期望：弹口径澄清卡（金额有 3 种算法）。

### B 口径歧义类——「上个月的履约超时率是多少？」
考察：不确定的地方会不会追问。期望：弹卡让用户选"超时运单÷已签收"还是"超时运单÷全部运单"。反例题（B19「订单量」）考察"不该问的别问"。

### C 实体歧义类——「8月苹果的订单量是多少？」
考察：「苹果」是商品品牌还是客户公司（苹果果业有限公司）？期望：弹卡二选一。反例题（C09「小米」）考察无歧义时直接作答。

### D 时间类——「最近的订单量是多少？」
考察：「最近」是几天？期望：弹卡（近7天/本月/近30天）。对照题（D01「最近一周」）考察明确时间不追问。

### E 多跳类——「8月超时运单最多的承运商是谁？」
考察：一句话能否拆成"运单→承运商"多表关联+排名。期望：不追问，直接算出答案（约 4 万条数据里找出超时最多的那家快递公司）。

### F 陷阱类——「8月的毛利率是多少？」
考察：数据里没有成本，正确行为是**老老实实说"数据不足"**。任何编造的数字都是错。这是语枢碾压对手的招牌题（对手在这类题上 0/4）。

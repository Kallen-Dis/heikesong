# DeepSeek 冷启动构思研究档案

本批用于赛题二方向一的方向优化，记录 10 次独立冷启动、36 个构思。实际模型均为 `deepseek/deepseek-flash`，以各份 normalized 结果的 `model` 字段为准。归档生成时间为 2026-10-12 UTC；本汇总依据现存 D01—D10 原文整理，没有重跑 API。

## 实验条件与完成状态

每次提示明确声明新会话、不了解任何既有作品或其他基线；输入为相同赛事背景和任务要求，另带不同实验编号。要求围绕 A 的三问提出至少 3 个机制不同的构思，并给出最小 demo、AI 职责、假设、反驳、首选、故事、架构和概念评分。提示中完整内嵌 `official_context.txt` 内容，10 份归档均核对为 `source_context` 出现在 `prompt` 中。

10/10 wrapper completed：`ok=true`、`exit_code=0`、`timed_out=false`，最后一个 usage step 的结束原因均为 `stop`；10/10 结果可解析为 JSON。完成状态表示 worker 产生了最终回答，不代表内容通过全部验收。

每次均记录 1 次 Read 权限拒绝，共 10 次。模型已有提示内嵌的完整上下文，拒绝后仍完成回答。因此不能把本批描述为“无工具拒绝”或“文件读取全部成功”。公开 D01—D10 的 `permission_denials` 与重复记录该拒绝的 `tool_errors` 已改为工具、次数及通用 `read_denied` 说明，删除原始私有路径和权限策略全文。模型 `result`、提示 `prompt`、usage、模型名、时间、提示哈希及背景均原样保留；临时目录中的原始 wrapper JSON 没有改写。

D06 的三个构思均缺少 `scores`、`total`、`range`，因此是 **JSON 可解析、wrapper completed，但评分 schema incomplete**。D06 的材料代理分完整；不据此推算缺失的构思评分。其余 9 次的构思评分字段完整。

归档没有记录可供复现实验的随机种子或温度，也没有实测 API 账单成本、墙钟延迟或重复稳定性。usage 中各 step 的 SDK `cost` 均为 0；这不能认定调用免费，也不能作为实际计费为零的证据。每份 JSON 保留 token/cache/reasoning 等原始 usage，不把 SDK 字段换算为未测量的费用。

## 共同点与有用差异

9/10 回答的首选属于语义契约或工具编译家族，D07 单独选择断言—证据图。共同主张是把平台提供给 AI 的单位由裸表或文档升级为可调用、有约束、带来源的机器接口；把本体用于类型、契约或治理；让旧数仓与 BI 继续运行，并共享语义定义。多份回答把模型职责放在意图解析、工具选择、参数绑定、歧义澄清和反馈解释，将取数、计算、权限和硬约束交给平台。

这说明本批在相同背景下集中形成了一个设计方向，不能据此证明原创性、产业领先、已验证优势或“本体是必要条件”。原文已反复指出语义层换皮、覆盖不足、维护成本高、历史日志不可得、双轨漂移及自我强化错误等反驳；这些反驳与主张一并保留。

可用于后续取舍的差异是：

- **D04/D02 的一源两译**：把融合演进变成同一语义定义同时更新 BI 和 AI 接口的可观察行为，比只画架构图更具体。
- **D03 的质量信号、D08 的失败重规划**：可以让模型看到不同失败原因后选不同局部修复；尚需真实轨迹验证，不能用固定动作顺序代替模型选择。
- **D07 的反证改变主张**：展示新证据如何撤回或限定结论，适合强调逻辑边界。其物流原因故事是概念示例，不能把预设的原因或置信数字当作因果验证。
- **D06 的任务银行**：可用已裁决的报表构造回归任务，但须检查报表口径，避免用模型生成答案再由同一模型自证。D06 缺失概念评分不会抹去这一机制差异。
- **D05 的影子提升、D09 的审批补丁**：演进步骤包含差异检查、人工批准和回滚。它们更适合作为主线的可审查扩展，是否需要取决于能否实际演示。
- **D02 的行为协议、D10 的日志自举**：前者学习分析流程，后者积累语义资产，不能混为一个机制；两者都依赖可得、合规且有代表性的使用记录。
- **D08 的上下文切片、D10 的证据切片**：前者解决给模型哪些语义，后者解决引用的是哪个数据版本；两种切片的目标和验收不同。
- **D01/D06 的跨域策略与凭证**：给出了数据不动和使用问责方向，但跨域证明、治理及实际能力未验证，不宜把概念凭证描述为真实可信数据空间已落地。

后续主线可从“受约束工具 + 反馈驱动局部修复 + 可审查证据”中选择可实际展示的闭环，再用一源两译解释与传统平台的融合。这里只提出从档案提炼的设计候选；没有对现有作品实现状态打分。

## 结论边界

未为本批联网补充产业来源。涉及语义层、厂商能力、成熟度或主办偏好的原文判断仍属待核；档案内赛事背景也只是保存的输入，不借本汇总更新赛程或官方规则。

部分回答把本体称为“必要条件”，或将内容寻址描述为“压制幻觉”。本批没有提供足以支持这些必要性或因果效果断言的来源与实验，汇总不采纳为已证实结论。哈希在后续设计中只作内容/版本比对和复现标识用途，不作为数据真实、语义正确、无幻觉或因果成立的保证。

工具契约、收据和审计只能形成明确的接口与复核路径；本批没有验证通用推理能力，也没有量化它们相对自由 SQL、RAG 或既有语义层的收益。原文中的对照实验均为建议，不能写成已经完成的实验结果。
